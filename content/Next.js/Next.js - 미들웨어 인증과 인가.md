# Next.js - 미들웨어 인증과 인가

## 질문

Next.js 미들웨어에서 인증과 인가를 어떻게 처리하나요? 브라우저에 저장된 인증 정보는 어떻게 가져오나요?

## 최적 답변

미들웨어는 요청이 페이지에 닿기 전에 실행됩니다. 그래서 화면을 그리기 전에 막을 수 있고, 로그인하지 않은 사람에게 보호된 화면이 잠깐 보였다 사라지는 일이 없습니다. 요청에 담긴 쿠키에서 토큰을 꺼내 검증하고, 없거나 유효하지 않으면 로그인 페이지로 보냅니다. 인가는 토큰 안의 역할 정보를 보고 처리해, 관리자 경로인데 역할이 관리자가 아니면 권한 없음 페이지로 돌립니다. 어떤 경로에서 돌지는 `config`의 `matcher`로 정합니다.

미들웨어는 브라우저가 아니라 서버 쪽 엣지 런타임에서 돕니다. 그래서 `localStorage`나 `sessionStorage`에는 접근할 수 없습니다. 그것들은 브라우저 안에만 있는 저장소입니다. 접근할 수 있는 건 쿠키뿐입니다. 쿠키는 요청 헤더에 자동으로 실려 오기 때문에 미들웨어가 요청 객체에서 바로 꺼내 쓸 수 있습니다. 그래서 로그인에 성공하면 토큰을 쿠키에 넣고, 서버가 응답 헤더로 내려주면서 `HttpOnly`를 붙이면 스크립트가 읽지 못해 XSS에 덜 노출됩니다. 엣지 런타임에서는 무거운 라이브러리를 쓰기 어려워, 미들웨어에서는 형식과 만료만 보고 실제 서명 검증은 뒤쪽에서 하는 식으로 나누기도 합니다.

## 반드시 포함할 키워드

- 페이지 도달 전 실행
- 쿠키에서 토큰 검증
- 역할로 인가 처리
- matcher로 경로 지정
- 엣지 런타임은 쿠키만 접근

## 자주 틀리는 표현

- 미들웨어에서 localStorage의 토큰을 읽어 검증한다.
- 미들웨어는 화면이 그려진 뒤에 실행된다.

## 한 줄 요약

미들웨어는 페이지 도달 전 엣지 런타임에서 돌며 요청 쿠키의 토큰을 검증·인가하고 matcher로 경로를 정하며, 엣지라 localStorage가 아닌 쿠키만 접근할 수 있다.
