# Lint - 린트 성능

## 질문

프로젝트가 커지면 린트가 느려집니다. 무엇 때문에 느려지고 어떻게 빠르게 하나요?

## 최적 답변

주된 비용은 두 가지입니다. 하나는 검사하는 파일 수이고, 다른 하나는 타입 기반 룰입니다. 타입 정보를 쓰는 룰은 타입스크립트 프로그램을 만들어 타입을 계산해야 해서 AST만 훑는 룰보다 훨씬 무겁습니다.

빠르게 하는 방법은 검사 대상을 줄이는 것입니다. `--cache`를 켜면 이전 결과를 저장해 바뀌지 않은 파일은 다시 검사하지 않습니다. 커밋 단계에서는 lint-staged로 변경된 파일만 검사합니다. CI에서는 캐시를 저장소에 남겨 재사용합니다. 타입 기반 룰은 정말 필요한 파일에만 적용하거나, 무거운 룰을 별도 설정으로 분리해 CI에서만 돌리기도 합니다. 정리하면 파일 수와 타입 기반 룰이 비용이고, 캐시와 변경 파일 한정으로 검사 범위를 줄이는 게 핵심입니다.

## 반드시 포함할 키워드

- 비용은 파일 수·타입 기반 룰
- 타입 프로그램 계산이 무거움
- --cache로 변경분만 재검사
- lint-staged로 변경 파일만
- 무거운 룰은 분리

## 자주 틀리는 표현

- 린트는 항상 빨라서 최적화할 게 없다.
- --cache를 켜면 룰이 바뀌어도 캐시를 그대로 쓴다.

## 한 줄 요약

린트 비용은 파일 수와 타입 기반 룰에서 오며, --cache와 lint-staged로 변경분만 검사하고 무거운 타입 룰을 분리해 범위를 줄인다.
