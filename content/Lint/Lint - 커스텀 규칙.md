# Lint - 커스텀 규칙

## 질문

커스텀 린트 규칙은 언제 만드나요? 만들기 전에 먼저 시도할 것은 무엇인가요?

## 최적 답변

커스텀 규칙은 문서로만 적어두면 지켜지지 않는 팀 컨벤션을 자동으로 강제할 때 만듭니다. 예를 들어 약어 금지, 특정 라이브러리 직접 호출 금지, 도메인 UI에서 라우터 호출 금지처럼 이 저장소만의 규칙은 기성 룰에 없으니 직접 만듭니다. 자동 수정(`fix`)까지 붙이면 규칙 위반을 지적하는 데 그치지 않고 고쳐줄 수도 있습니다.

다만 만들기 전에 순서가 있습니다. 금지하려는 게 셀렉터나 import 경로로 표현되면 `no-restricted-syntax`·`no-restricted-imports` 같은 코어 룰로 설정만으로 처리합니다. 여기서 표현이 안 되는 복잡한 조건이거나, 자동 수정이나 정교한 메시지가 필요할 때만 커스텀 규칙으로 갑니다. 커스텀 규칙은 만들고 테스트하고 배포하고 유지하는 비용이 있으므로, 설정으로 되는 1차 방어를 먼저 소진한 뒤의 선택입니다.

## 반드시 포함할 키워드

- 문서로 안 되는 팀 컨벤션 자동화
- 저장소 고유 규칙
- fix로 자동 수정까지
- 먼저 no-restricted-* 시도
- 커스텀은 유지 비용 있는 최후 수단

## 자주 틀리는 표현

- 팀 규칙은 무조건 커스텀 플러그인부터 만든다.
- 커스텀 규칙은 만들면 유지 비용이 들지 않는다.

## 한 줄 요약

커스텀 규칙은 문서로 안 지켜지는 저장소 고유 컨벤션을 강제할 때 만들되, no-restricted-* 코어 룰로 안 되는 복잡한 조건·자동수정이 필요할 때의 최후 수단이다.
