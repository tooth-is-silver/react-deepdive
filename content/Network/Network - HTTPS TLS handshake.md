# Network - HTTPS TLS handshake

## 질문

HTTPS는 무엇을 보장하고, TLS 핸드셰이크는 어떻게 동작하나요? 대칭키와 비대칭키를 왜 함께 쓰나요?

## 최적 답변

HTTPS는 HTTP를 TLS 위에서 주고받는 방식으로, 통신 내용을 암호화하는 기밀성, 중간에 변조되지 않았음을 보장하는 무결성, 접속한 서버가 진짜인지 확인하는 서버 인증을 제공합니다. 핸드셰이크는 클라이언트가 지원하는 암호 스위트를 담아 ClientHello를 보내고, 서버가 ServerHello와 공개키가 담긴 인증서로 응답하는 것으로 시작합니다. 클라이언트는 그 인증서를 신뢰된 CA 체인으로 검증해 서버 신원을 확인하고, 이어서 양쪽이 이후 통신에 쓸 대칭 세션 키를 안전하게 합의합니다.

대칭키와 비대칭키를 함께 쓰는 이유는 성능과 안전을 모두 얻기 위해서입니다. 비대칭키는 사전 공유 없이 안전하게 키를 교환할 수 있지만 연산이 느려서, 세션 키를 합의하는 초기 단계에만 씁니다. 실제 데이터는 빠른 대칭키로 암호화합니다. 즉 "느리지만 안전한 방식으로 열쇠를 나눠 갖고, 빠른 방식으로 본 통신을 한다"는 구조입니다. TLS 1.3은 이 핸드셰이크를 1-RTT로 줄이고 재접속 시 0-RTT까지 지원해 지연을 크게 낮췄습니다.

## 반드시 포함할 키워드

- HTTP over TLS
- 기밀성·무결성·서버 인증
- 인증서와 CA 검증
- 세션 키 합의
- 대칭키(빠름)와 비대칭키(안전)
- TLS 1.3 1-RTT

## 자주 틀리는 표현

- HTTPS는 데이터 전체를 비대칭키로 암호화한다.
- 인증서는 데이터를 암호화하는 열쇠다.

## 한 줄 요약

HTTPS는 TLS로 기밀성·무결성·서버 인증을 제공하고, 느린 비대칭키로 세션 키를 안전하게 합의한 뒤 빠른 대칭키로 실제 통신을 암호화한다.
