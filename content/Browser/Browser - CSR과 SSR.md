# Browser - CSR과 SSR

## 질문

CSR과 SSR의 차이는 무엇인가요? SSR의 장점으로 꼽는 SEO는 왜 중요한가요?

## 최적 답변

CSR은 거의 빈 HTML과 자바스크립트 번들을 내려주고 브라우저가 화면을 그립니다. 첫 화면이 뜨기까지 번들을 받고 실행하는 시간이 걸리지만, 한 번 뜨고 나면 페이지 전환이 빠릅니다.

SSR은 서버가 HTML을 완성해서 내려줍니다. 브라우저는 받자마자 보여줄 수 있어 첫 화면이 빠르고 검색 로봇도 내용을 읽을 수 있습니다. 대신 요청마다 서버가 렌더링하니 부하가 늘어납니다. 지금은 둘 중 하나를 고르는 문제가 아니라, Next.js처럼 서버에서 HTML을 만들어 보낸 뒤 브라우저에서 이벤트를 붙이는(hydration) 방식으로 첫 화면과 이후 전환을 모두 챙깁니다.

SEO가 중요한 이유는, 검색 유입이 광고비를 계속 쓰지 않아도 들어오는 통로이기 때문입니다. 검색 결과에서 위에 있을수록 클릭이 몰려 순위가 곧 트래픽이고 매출로 이어집니다. 검색 로봇은 기본적으로 받은 HTML을 읽는데, CSR로 만든 페이지는 처음 받은 HTML이 비어 있어 내용 없는 페이지로 보일 수 있습니다. 링크 공유 시 제목·설명·미리보기 이미지가 뜨려면 그 메타 정보도 처음 받은 HTML에 있어야 합니다.

## 반드시 포함할 키워드

- CSR은 빈 HTML + 번들
- SSR은 완성 HTML
- hydration으로 이벤트 부착
- 검색 로봇은 초기 HTML을 읽음
- 메타 태그도 초기 HTML에 필요

## 자주 틀리는 표현

- CSR도 검색 로봇이 자바스크립트를 다 실행해 읽으니 SEO 차이가 없다.
- SSR은 페이지 전환까지 항상 CSR보다 빠르다.

## 한 줄 요약

CSR은 빈 HTML에 번들로 브라우저가 그려 전환이 빠르고, SSR은 완성 HTML을 내려 첫 화면·SEO에 유리하며, 검색 로봇이 초기 HTML을 읽기에 메타 정보도 거기 있어야 한다.
